202. Happy Number — Fast & Slow Pointers (Floyd's cycle detection)

Replacing n with the sum of its squared digits, over and over, forms a chain that must loop. 🐢 slow moves 1 hop, 🐇 fast moves 2 hops. Fast either lands on 1 (happy) or laps slow inside a loop that doesn't contain 1 (not happy).

Why there's always a loop: each next number is completely determined by the current one, and once a number has 4+ digits the next is much smaller (9999 → 324). The values get trapped below ~243, so some value has to repeat. Once a value repeats, the chain goes round that loop forever.

      
Happy numbers loop too. 1 → 1² = 1, so they end in a loop of size 1. The real question is "is the loop just {1}?"

      
Why fast must catch slow: once both are inside the loop, each round slow moves +1 and fast moves +2, so fast gets 1 hop closer to slow every round. The gap goes 5, 4, 3, 2, 1, 0 → they meet. Fast can't jump over slow, because the gap only ever shrinks by exactly 1.

      
No set of seen numbers needed: two variables replace a hash set.

    

    

      
TimeO(log n)
        One hop costs O(digits) = O(log n). The first hop shrinks a d-digit n to at most 81·d, and after that every value is below 243, so the tail and the loop have constant length. That adds up to O(log n) for the first hop plus O(1) rounds of O(1) work.

      
SpaceO(1)
        Only two integers (slow_pointer, fast_pointer) plus the helper's locals. A hash-set version would need O(log n) for the values it has seen.
