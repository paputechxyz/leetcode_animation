783. Minimum Distance Between BST Nodes — In-order DFS

An in-order walk (left, node, right) of a BST visits the values in sorted order. In a sorted list the closest pair is always two neighbours, so compare each value only with the one visited just before it (prev).

Why in-order = sorted: in a BST everything in the left subtree is smaller and everything in the right subtree is larger. Visiting left subtree → node → right subtree therefore produces the values in increasing order.

      
Why only neighbours: if a < b < c then c − a = (c − b) + (b − a), which is bigger than either gap. A non-neighbour pair can never be closer than the neighbours between them.

      
Neighbours aren't always parent/child. The value before a node is the rightmost node of its left subtree, or an ancestor further up. prev handles both, because it's just "the last value visited".

      
Since values come out increasing, node.val − prev is always positive, so no abs() is needed.

    

    

      
TimeO(n)
        n = number of nodes. Each node is visited once, with one subtraction and one min per node. There's also one call per empty child (n + 1 of them), which is O(1) each.

      
SpaceO(h)
        h = tree height, for the recursion stack: O(log n) for a balanced BST, O(n) for a chain. Beyond that only prev and best are stored, with no list of values.
