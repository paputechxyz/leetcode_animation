Service Dependency Load Balancer — memoized DFS + min-heap

For each service reachable from the entrypoint, collect the set of everything it depends on, directly or indirectly. Its load is the size of that set; shared dependencies are counted once because it's a set. Then push every (load, name) into a min-heap and pop them all to get the boot order.

      Why a set? api reaches db through both user and orders. Adding to a set ignores the duplicate, so db is counted once and api's load is 3, not 4.

      Why memo? Each service's set is computed once. The next time it's needed, for example db from a second parent or in the heap loop, it's returned immediately.

      Bonus: if A depends on B, then A's set contains B plus all of B's set, so load(A) > load(B). That means sorting by load always boots dependencies before the services that need them.
    

    

      
TimeO(V·(V+E) + V log V)
        V = reachable services, E = dependency edges between them. Each service is expanded once thanks to memo, but merging a child's set can copy up to V names per edge. The heap adds V pushes and V pops at O(log V) each. Parsing the input is linear in its length.

      
SpaceO(V²)
        memo stores a set for every service, and each set can hold up to V names. adj, the heap, the boot order and the recursion stack (depth ≤ V) are O(V + E).
