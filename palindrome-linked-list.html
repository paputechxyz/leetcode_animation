234. Palindrome Linked List — Fast & Slow Pointers + Reverse Second Half

A singly linked list can't be read backwards, so we make the second half backwards. Find the middle with slow/fast, reverse from the middle, walk both halves inward comparing values, then reverse again to put the list back.

Linked list (arrows = the real .next pointers; they change during the reversal)

Code (your solution)


    

      
1. Find the middle. Same as Middle of the Linked List: slow +1, fast +2, so slow stops at the middle (the 2nd middle for even lengths).

      
2. Reverse from slow. Flip each .next to point backwards. The second half can now be walked from the end towards the middle.

      
3. Compare. One pointer walks from head and one from the old tail. Stop when second_half runs out. The node before the middle still points to the middle (now the reversed tail), so for odd lengths the middle node gets compared with itself.

      
4. Restore. Reversing again puts every arrow back, so the caller's list is unchanged.

    

    

      
TimeO(n)
        n = number of nodes. Finding the middle takes n/2 rounds, each reversal touches n/2 nodes, and the compare does at most n/2 pairs. That's a constant number of linear passes.

      
SpaceO(1)
        Just a handful of pointers (slow, fast, prev, curr, next, first_half, second_half). The list is reversed in place, with no array copy and no recursion.
