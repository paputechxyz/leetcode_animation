46. Permutations — Backtracking with a used[] array

Fill path one position at a time. At each position, try every number that isn't used yet, recurse, then undo (pop + unmark) so the next choice starts clean. A full path is one permutation.

Recursion tree (each node = the number just appended to path)

current call / number being chosen on the current path (call waiting) full path → appended to res finished, undone used[i] is True → continue

      Order matters here, so every call loops over all of nums from index 0, unlike Combinations,
      which starts at start. [1,2] and [2,1] are both answers.

      used[i] stops a number from appearing twice in one path. Indexes already in path are skipped with continue.

      Undo in reverse order. path.pop() and used[i] = False put the state back exactly as it was before choosing nums[i],
      so the next loop iteration sees a clean slate.

      path.copy() saves a snapshot; path itself keeps changing.
    

    

      
TimeO(n·n!)
        There are n! permutations (n = len(nums)), each copied in O(n). The tree has fewer than e·n! calls in total, and each runs an O(n) loop over used, so the total is still O(n·n!).

      
SpaceO(n)
        Extra memory is the recursion stack (n deep), path (≤ n) and used (n). The output holds n! lists of length n, so O(n·n!) if you count it.
