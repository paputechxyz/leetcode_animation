424. Longest Repeating Character Replacement — Sliding Window

A window is fine if window length − count of its most common letter ≤ k: keep the most common letter and repaint everything else. Grow the window to the right. When it needs more than k repaints, slide the left edge.

String & window (blue = letter we keep, amber = letters we'd repaint)

kept (most common letter) repainted (uses 1 of k) too many repaints: over k outside the window best window so far

Code


    

      
Repaints needed for a window = its length − the count of its most common letter. If that's ≤ k, the whole window can become one letter.

      
Grow right, slide left. Each right adds one char. If the window now needs more than k repaints, drop s[left]. The window is never smaller than the best so far, so it only ever slides or grows.

      
Why max_freq never goes down: the answer only improves when some letter reaches a new higher count. A stale (too-high) max_freq can only keep the window at its current size and slide it along. It can never let the window grow wrongly, so recomputing it isn't needed.

    

    

      
TimeO(n)
        n = len(s). right moves n times and left moves at most n times in total, so each char enters and leaves the window once. Each move is O(1) dictionary work.

      
SpaceO(1)
        count holds at most 26 keys (uppercase letters), whatever n is. More generally it's O(σ) for an alphabet of σ letters.
