287. Find the Duplicate Number — Fast & Slow Pointers (Floyd's cycle detection)

Read the array as arrows i → nums[i]. The duplicate value has two arrows pointing into it, so it's exactly where the path from index 0 enters a loop. Phase 1 finds a point in the loop. Phase 2 finds the entrance, which is the duplicate.

Why there's a loop at the duplicate: values are 1..n, so every index points somewhere valid and nothing points to index 0. Start at 0 and follow arrows: you must eventually revisit a node. The first revisited node has two arrows into it (one from the path, one from the loop). That means two indices hold the same value: the duplicate.

      
Phase 1 (slow +1, fast +2): same as Happy Number. Once both are in the loop, the gap shrinks by 1 per round, so they must meet somewhere in the loop.

      
Phase 2, the magic part: let F = hops from the start to the entrance and C = loop length. At the meeting point slow walked k hops and fast walked 2k, so the extra k is a whole number of laps (a multiple of C). From the meeting point, F more hops gives k + F total, which is F past the entrance plus whole laps, so it lands exactly on the entrance. So reset slow to the start, move both 1 hop at a time, and after F hops they meet at the entrance.

    

    

      
TimeO(n)
        n + 1 = len(nums). In phase 1, slow meets fast before finishing its first lap of the loop, so it takes at most F + C ≤ n + 1 hops. Phase 2 takes F more. Each hop is one array read.

      
SpaceO(1)
        Only the two pointers, slow and fast. The array is read but never modified, and there's no hash set of seen values.
