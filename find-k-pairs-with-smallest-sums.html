373. Find K Pairs with Smallest Sums — one candidate per row, in a min-heap

Write every pair's sum in a grid. Each row is sorted, like a line of people ordered by sum, so only the front of each line can be the next-smallest pair. Keep those fronts in a heap. Each round, take the smallest front; the next cell in that row then steps up to become the new front. Do this k times.

All pair sums (row = nums1[i], column = nums2[j], cell = their sum)

front of its row (in the heap) taken this round in the answer (#order) not reached yet row never used (only first k rows)

      The three things to understand:
      
    
        
  1. Rows are sorted, so a row's smallest unused pair is always its leftmost unused cell, the "front".
    2. 
        
  2. The next answer must be one of the fronts. The heap holds exactly one front per row and hands back the smallest.
    3. 
        
  3. After taking a row's front, push the cell to its right. If there isn't one, that row is used up.
    4. 
      

      Only the first k rows are used: column 0 is sorted too, so a row further down starts behind k smaller pairs and can't make the top k.
    

    

      
TimeO(k log r)
        r = min(len(nums1), k), the number of rows used. There are at most k rounds, and each pops one entry and pushes at most one, on a heap of at most r entries.

      
SpaceO(r)
        The heap holds one front per row, so at most r entries. The answer list adds O(k) if you count it.
